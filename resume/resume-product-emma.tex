\section{Professional Experience}

\entry{\href{https://karya.in}{Karya}}{Senior Product Engineer (Product Owner)}{Bengaluru, India}{2024 -- Present}
{\small\textit{Product owner for a B2B data-collection and worker-payments platform. Worked directly with the CTO and with operations, finance, and support. Owned the roadmap and backlog from problem to production.}}
\begin{itemize}
  \item \textbf{Roadmap:} Owned \textbf{Platform by Karya} end to end, a B2B operations product with \textbf{65M+ tasks}, \textbf{70+ languages}, and deployments in \textbf{6 countries}. Turned task creation into \textbf{30+ components} so operations configure each program, including for low-bandwidth and low-literacy users, instead of commissioning a new build.
  \item \textbf{AI evaluation:} Ran the same product for programs that score model output against real use: \textbf{Samiksha} with Microsoft (\textbf{23,000+} real-world queries, \textbf{150,000+} human evaluations) and an \textbf{Anthropic} evaluation (\textbf{10,000} community queries, \textbf{30,000+} tasks, 7 languages).
  \item \textbf{Requirements:} Owned \textbf{Task Preview} from the problem through production. Wrote the PRD with user stories, acceptance criteria, and non-goals. Every new task stays in Preview, payouts off, until operations approves it. Task issues fell by \textbf{close to 90\%}, and a data operation takes \textbf{more than 50\% less time}.
  \item \textbf{Prioritization:} Put a shared launch gate and \textbf{Task Health} ahead of one-off task builds. \textbf{7 automated checks} (assignments, microtasks, completion policy, upstream tasks, avatar linking, rejected work, and boxes) each open the screen that fixes the blocker, so coordinators clear them without an engineer.
  \item \textbf{Data:} Shipped an \textbf{LLM-backed} plain-English query tool over live PostgreSQL, with history and reusable templates, so operations pull live data for a decision without asking engineering for SQL.
\end{itemize}
